# 面向工作室的 3D 动作生成：GST 持枪瞄准 Showcase

通用文生动作模型能生成看起来合理的运动，但游戏工作室要的东西更窄也更硬：动作必须遵守角色的骨骼契约、匹配特定的持枪姿态与手势序列、使用指定的片段长度、保持支撑脚稳定，并以 FBX 或 Unreal 动画资产的形式交付，可供评审与复用。

GST 的合作把 Kimodo 适配到了 16 个站姿步枪/瞄准（AIM）动作上。三轮微调把项目从一条能跑通的转换链路，推进到语义对齐的动作，再推进到显式优化脚部稳定性。

| 项目事实 | 当前证据 |
| --- | --- |
| 合作工作室 | GST |
| 基础动作模型 | Kimodo-SOMA-RP，搭配 SOMA77 中间骨骼 |
| 专属数据集 | 16 个站姿步枪/瞄准手势 |
| 训练迭代 | 0714 基线链路 → 0716 语义与时长对齐 → 0720 脚部稳定性优化 |
| 最终对比契约 | 全部 16 个最终动作均按对应 GT 片段时长生成 |
| 代表性物理结果 | 四个已报告动作的支撑脚水平漂移代理指标下降 50–74% |
| 交付路径 | 目标角色动画 → SOMA77 训练数据 → 微调生成 → 目标角色 FBX/Unreal 动画 |

## 1. 实际差距：模型输出还不等于工作室可用的动画

有四个彼此独立的生产问题需要解决：

1. **骨骼不匹配。** 已有的 AdamAll 或目标角色动画，无法被基于 SOMA77 的模型直接使用。
2. **动作语义弱。** 「停止信号」这类短标签，并没有说明哪只手动、枪怎么动、角色如何回到准备姿态。
3. **对比无效。** 生成片段与参考时长不一致时，看起来更好或更差可能只是因为节奏不同。
4. **脚部滑移（foot skating）。** 改进上半身手势的同时，名义上「踩住」的脚仍可能从地面上滑走。

解决方案把重定向、经过验证的格式转换、微调、受控生成与引擎侧评审串起来，而不是把 prompt 当成整个产品。

## 2. Showcase A —— Show_AssaultAim：从通用站姿到特定持枪手势

### 背景与问题

需要的不是简单的「一个突击动作」。评审确认的描述是：

> 一个人持步枪，做一个短促、具攻击性的突击准备动作，把枪向上挥动两次，然后左手向前抬起，再回到瞄准姿态。

基础模型能产出看似合理的持枪站姿，但并不能稳定复现这个有序的手势。而且只有让生成使用与 GT 片段相同的时长，对比才可靠。

### 迭代过程

- **0714：** 打通 NPZ → SOMA77 FBX → Unreal 预览的完整链路，并为全部 16 个动作生成首轮结果。
- **0716：** 用可观察的英文肢体动作描述替换粗略的动作名，并让每个动作按其对应 GT 时长生成。
- **0720：** 在保留上半身手势的同时，加入修复后的脚部接触监督、更强的 root/脚部权重，以及一个显式的防滑移目标。

## 3. Showcase B —— TacticalSign_CTMAim：诊断并纠正脚部滑移

### 语义更新之后出了什么问题

0716 轮改进了动作描述与时长，但脚部滑移变得更明显。这个问题不是简单加大脚部位置损失就能解决的。重定向后的 GT 片段本身带有轻微悬浮与抖动，因此原始的接触阈值产生了碎片化的监督信号：

- 基础模型在这 16 个本地 prompt 上的输出，脚部接触比例均值约为 **0.960**。
- 原始保存的 GT 接触均值约为 **0.273**。

这个基线数字并非来自 Kimodo 原始训练集，而是基础模型在这组特定的 16 条持枪动作 prompt 上的输出分布，被用作一个本地的「踩地」先验。

### 优化要点

| 改动 | 为什么重要 |
| --- | --- |
| 用 `velocity=0.75 m/s`、`foot height=0.16 m`、`toe height=0.10 m` 重算接触标签，并做一帧的间隙填充 | 在不采用「统计上最接近但物理上过于宽松」的阈值的前提下，恢复了连贯的支撑脚区间 |
| 把脚部关节损失权重从 0.5 提到 3.0 | 修好标签之后，重新拿回直接的几何控制力 |
| 把 root 位置权重从 1.0 提到 3.0、root 朝向权重从 0.5 提到 1.0 | 减少 root/胯部漂移——否则即便局部脚部关节是稳的，脚也会跟着整体漂移 |
| 加入以接触为条件的脚部滑移损失，权重 4.0 | 只在修复后的连续 GT 接触帧上，惩罚预测的水平脚/脚趾速度 |
| 保持上半身权重高于脚部权重 | 避免为了贴合重定向噪声而牺牲步枪与指挥手势 |

## 4. Showcase C —— 让生成的动作扛过 FBX/Unreal 交付链路

如果转换或重定向会改变动画，微调再成功也没有意义。因此生产链路用 Unreal 做语义重定向、用 Blender 做确定性的 FBX/NPZ 转换：

1. 在 Unreal 中把 AdamAll 或目标角色动画批量重定向到 SOMA77。
2. 导出 SOMA77 动画 FBX。
3. 把 SOMA77 FBX 转成 Kimodo NPZ，同时保留 77 个关节、root/胯部运动、帧率与片段长度。
4. 用微调后的模型生成 SOMA77 动作。
5. 把 NPZ 转回 SOMA77 FBX，并批量重定向到目标角色。
6. 在 Unreal 里评审目标角色动画，并连同映射与脚本一起打包 FBX/UE 资产。

一次抽样的往返验证覆盖了三个 FBX 片段与三个 NPZ 片段的两个方向。六个样本全部通过 5 mm 的位置与脚部阈值，保留了 77 个 NPZ 关节与至少 78 根 FBX 骨骼（含 `Root`），并保持帧数一致。该样本中报告的最大位置偏差为 **0.010 mm**。

0716 迭代期间还暴露出一个具体的交付 bug：当 Unreal 把冗余的顶层骨架变换曲线也解释进来时，较长的纯动画 FBX 可能发生塌陷。导出端的修复做法是：用一个极小的简化阈值移除恒定的 object 级曲线，同时保留每一根 pose bone 的关键帧与完整 action 范围。这正是这套能力要包含转换验证与引擎预览、而不只看训练损失的原因。

## 5. 三轮迭代证明了什么

| 轮次 | 生产问题 | 改动 | 该轮之后的证据 |
| --- | --- | --- | --- |
| 0714 | 没有可复用的端到端路径 | 搭建重定向、转换、生成、Unreal 预览与基线/GT/最终对比 | 16 个首轮持枪瞄准输出与一条可重复的评审回路 |
| 0716 | Prompt 与时长未与参考动作对齐 | 加入详细的可观察描述与匹配 GT 的生成长度 | 全部 16 个动作变得可直接对比；脚部滑移浮现为下一个主要缺陷 |
| 0720 | 上半身手势清晰了，但支撑脚在漂移 | 修复接触标签、加入滑移损失、提高脚部/root 权重 | 四个已报告动作在保留持枪手势的同时，支撑脚漂移代理指标下降 50–74% |

这些证据支持的是：在当前站姿步枪/瞄准这一特定领域内，存在一套可用的专属动作生成工作流。它尚未证明能广泛泛化到位移、蹲伏、匍匐、掩体交互或任意角色。

## 6. 可复用的工作室交付物

这套能力可以作为一个整体包交付给其他角色或工作室，而不是一次性 checkpoint：

- 微调后的 Kimodo 模型；
- 双向的 Unreal IK Rig 与 IK Retargeter 资产；
- 骨骼映射与重定向姿态配置；
- 源 → SOMA77 与 SOMA77 → 目标角色的批量脚本；
- 经过验证的 FBX ↔ Kimodo NPZ 转换器；
- prompt 描述表与时长控制；
- 目标角色的 FBX 或 Unreal 动画资产；
- 视觉对比与脚部漂移评测工作流。

## 7. 下一个试点：在不丢失现有控制力的前提下扩大覆盖

下一份数据集应当加入位移、转向、蹲伏、匍匐、掩体探头、受击反应，以及边走边打停止或前进手势这类复合动作。每个片段都应配一段简短、可观察的英文描述——最好以「A person…（一个人……）」开头，描述道具、姿态、肢体轨迹、顺序与回归姿态，而不只描述意图。

试点验收应当综合语义正确性、节奏、脚部稳定性、重定向质量、动画修改负担与引擎内评审。当前 16 个动作的结果是一次聚焦验证：证明针对性微调能解决一个工作室专属的动作族；更广的动作与角色覆盖仍是下一步要验证的事。
