# RefMatch：以参考图驱动的 2D 资产区域配准与稳定裁剪工作台

在游戏 2D 美术流程中，裁剪的难点从来不是下刀，而是**对齐**。同一视觉主体常常同时以多种形态存在：成百上千张技能动画帧、风险图与合规图版本、不同分辨率的 UI 与角色主视觉变体。要把参考资产上的一个业务区域对应到这些目标上，传统做法是逐份、逐帧手工对齐再裁剪——慢、易错、难规模化。

RefMatch 把这一步产品化：在参考图上标注一次感兴趣区域（**ROI**），然后在另一张目标图、乃至整段视频/帧序列上自动配准、稳定裁剪并给出质量评分——全程本地运行、GPU 加速。它不解决「画面里是什么」这个语义问题，而是解决「这个区域在另一个资产里对应哪里、如何稳定地裁出来」这个几何配准问题。

## 1. 应用场景：同一内容的多种资产，仍需要一套可复现的区域对应关系

在生产中，RefMatch 面向的是一类反复出现的裁剪工作：它们共用同一套配准与裁剪引擎，差别主要在输入形态与入口。

| 典型场景 | 要做什么 | 常见失效模式 |
| --- | --- | --- |
| 技能 / 特效局部裁剪（Skill Video Cut） | 在关键帧上标出主体；跨视频或图像序列逐帧裁出相同局部内容 | 主体或镜头运动（平移/缩放/旋转）导致固定窗口漂移、构图抖动、输出尺寸对不齐 |
| 风险图 → 合规图对应裁剪 | 在风险图上标出业务区域（审核 / mosaic / 水印 / 低清版）；从合规图（已过审高清母版）裁出同一区域 | 画布、分辨率与留白不同，肉眼对齐成本高且不一致——裁错、漏裁 |
| UI / HUD 多版本区域对齐 | 在一个 UI 版本上标出控件区域；在另一分辨率 / 地区版本 / 皮肤上裁出对应区域 | 布局缩放或偏移；人工对齐成本随页面数线性增长 |
| 角色主视觉 / 道具表构图提取 | 以固定的头像 / 半身 / 图标构图为参考；从同一角色的其他版本表中批量抽出标准尺寸裁图 | 多次走查产生不一致的裁剪基线与输出规格 |

当资产更新或改版时，同样的工作要重来一遍：重新定位、重新对齐、重新裁剪、重新检查。瓶颈不只是「裁剪慢」，而是缺少一条可复现的工程路径：复用参考区域、约束裁剪基线、并统一输出规格。

## 2. 问题本质：参考 ROI 与目标资产之间没有工程化的区域配准

传统流程在**参考区域**与同一内容的众多目标资产之间，缺少稳定、可复现、可扩展的配准环节。操作员充当了一层**人工配准层**：逐份或逐帧肉眼对齐、手工裁剪，再用返工来吸收误差。

这一步把「看起来一样」转成**像素级对应关系**。它是裁剪交付中人力最密集、最依赖经验、也对改版最敏感的环节。在动画序列与多版本资产中，姿态与画布通常不同；一次改版就可能迫使整批重新对齐、重新裁剪。

![RefMatch 配准缺口与人工成本增长](assets/images/refmatch/refmatch-problem-model.svg)

| 核心痛点 | 传统做法 | RefMatch 如何应对 |
| --- | --- | --- |
| 人工区域配准 | 逐份 / 逐帧肉眼对齐；跨画布、跨分辨率更难 | 特征匹配 + RANSAC 变换估计，建立从参考 ROI 到目标的几何对应关系 |
| 跨帧不稳定 | 手工裁剪抖动；主体漂移出画；留白过大 | 跟踪 + 亚像素细化让区域持续更新；输出跨帧保持稳定 |
| 输出规格不一致 | 尺寸、构图与留白各随个人习惯 | 重采样到参考 ROI 网格，输出到锁定尺寸的画布 |
| 质量不可度量 | 「看着裁出来了」，但错位或空裁很难发现 | 置信度、内点比例、重投影误差与 ZNCC 内容相关性把每个结果量化 |
| 吞吐受限 | 成百上千帧 / 多个版本逐张处理 | 异步批任务 + 进度反馈 + 一键导出（序列 ZIP / 视频 / 静帧） |
| 改版复用率低 | 资产更新就得全部重做 | 参考 ROI 与参数可复用；改版后直接重跑，无需重建对应关系 |

## 3. 产品定位：面向 2D 资产配准与裁剪的参考 ROI 工作台

![工作台总览](assets/images/refmatch/cover.png)

> **在参考图上标注一次区域，然后在另一张图或整段序列上自动对齐并稳定裁剪。**

RefMatch 是一个本地运行、由参考图驱动的视觉配准与裁剪工具。它把参考图、目标资产、ROI 与匹配参数保持在同一个上下文中。匹配流水线依次执行特征对应、变换估计、可选的亚像素细化、稳定裁剪与质量评分，并为视频 / 序列提供逐帧跟踪与批量导出。

两图对应裁剪，跑一次**参考对齐**或**快速匹配**即可。视频与序列则跑批量跟踪任务，可在**参考匹配**、**递归匹配**与**固定框裁剪**之间选择——三者共用同一套裁剪与输出规则。

| 项目 | 产品契约 |
| --- | --- |
| 输入 | 一张参考图 + 一个 ROI，外加一张目标图，或一段视频 / 帧序列目录 |
| 输出 | 目标上对应区域的稳定裁剪结果（静帧或逐帧序列），以及可选的对比 / 叠加 / 差异视图 |
| 统一入口 | 资产准备、ROI 选择、匹配运行、结果与导出在同一个本地工作台内协作完成 |
| 引擎职责 | 特征匹配、RANSAC 变换估计、ECC 亚像素细化、ZNCC 质量仲裁，以及参考网格上的稳定裁剪 |
| 运行原则 | 参考 ROI 的像素网格即输出基线；普通的预览 / 查看动作不会修改源资产 |
| 适用范围 | 图像对的一次性配准，或视频 / 序列的逐帧批量跟踪与导出 |

产品边界是**区域配准与裁剪**这一步：RefMatch 不做语义识别（例如「找出所有敌人」），也不替代美术创作或最终人工评审。它面向的是两图 / 多帧内容相同、主要在位置、尺度或轻微透视上存在差异的对应裁剪。

## 4. 统一工作台体验

前端把「观察 → 配置 → 运行 → 验收」组织成四步流程，配一个可调整宽度的右侧参数与质量侧栏，让一次配准任务停留在单页内完成。

| 区域 | 主要信息与操作 |
| --- | --- |
| 步骤条 | 资产准备 → 选择参考 ROI → 运行匹配 → 结果与导出；下划线滑动指示进度；提供明确的上一页 / 下一页导航 |
| 资产准备 | 上传参考图与目标图；在序列跟踪中上传视频，或输入 / 选择本地序列目录或 glob 并探测 |
| ROI 画布 | 在参考图上拖出矩形；可移动、缩放或重置为整图；在参考裁剪模式下，参考图与目标图并排显示以便比对 |
| 参数面板 | 匹配器、变换模型、跟踪模式、置信度与 RANSAC 阈值、输出裁剪，以及折叠的高级设置 |
| 结果视图 | 参考裁剪：裁剪结果 / 参考对比 / 叠加 / 差异；序列跟踪：裁剪结果 / 匹配详情 / 源序列 |
| 匹配质量与日志 | 质量评分环、内点比例、重投影误差、内容相关性、设备信息与运行日志 |

纯观察类操作（缩放、平移、显隐、视图切换）与处理过程相互独立：它们只更新显示状态，既不改变匹配输入，也不回写源资产。

## 5. 核心工作流

![RefMatch 核心工作流与匹配流水线](assets/images/refmatch/refmatch-core-workflow.svg)

### 5.1 三个运行入口

一套引擎支撑两种模式和三个入口；它们的差别在于输入形态与输出规模。

| 入口 | 模式 | 最适合 | 后端能力 |
| --- | --- | --- | --- |
| 参考对齐 | 参考裁剪 | 风险图 ↔ 合规图、跨版本 UI 的两图裁剪 | 单图像对配准；返回裁剪与对比视图 |
| 快速匹配测试 | 序列跟踪 | 在批量前用单帧验证 ROI 与匹配质量 | 单图像对匹配；快速参数自检 |
| 批量序列处理 | 序列跟踪 | 完整技能视频 / 动画序列的稳定逐帧裁剪 | 异步逐帧跟踪 + 进度 + 批量导出 |

### 5.2 匹配流水线

每次运行都执行同一条确定性流水线：

1. **特征对应** —— 用选定的匹配器，在参考 ROI 与目标之间建立像素级匹配。默认深度匹配器为 RoMa（在风格化动画与弱纹理上更稳）；另有 LoFTR、SIFT、ECC 与光流可选。
2. **变换估计** —— 用 RANSAC 从对应关系中鲁棒估计几何变换；模型从平移到单应变换可选，并支持从最简单模型自动升级到更丰富的模型。
3. **亚像素细化** —— 可选的 ECC 光度对齐，在亚像素级别微调特征估计，降低残余偏移。
4. **稳定裁剪** —— 通过 `warp_to_reference_grid` 把参考 ROI 像素网格重采样到目标上，保持内容对应严格、输出尺寸锁定，避免黑边与错位。
5. **质量评分** —— 由置信度、内点比例、重投影误差与空间覆盖率加权得到；ZNCC 内容相关性用于仲裁候选变换并校正评分。

### 5.3 变换模型与裁剪选项

| 类别 | 选项 | 说明 |
| --- | --- | --- |
| 变换模型 | 平移 / 正置矩形（默认）/ 独立缩放的正置矩形 / 相似 / 仿射 / 单应 / 自动 | 正置保持 ROI 轴对齐、不带旋转自由度——最适合 UI 与动画元素；自动模式从最简单模型逐级升级 |
| 裁剪模式 | 参考 ROI 网格（默认）/ 紧致匹配 AABB / 透视展开 | 参考网格重采样到 ROI 尺寸、两侧对应严格；紧致取 AABB；展开则对映射后的四边形做矫正 |
| 填充方式 | 黑色（默认）/ 边缘延伸 / 镜像 / 纯色 | 变换后越界采样点的填充策略 |
| 输出尺寸 | 宽 / 高（0 = 参考 ROI 原始尺寸） | 两者都设 → 精确尺寸；只设一个 → 保持宽高比 |

### 5.4 三种跟踪模式（序列跟踪）

对视频 / 序列，三种跟踪模式按运动特性在稳定性与速度之间取舍。

![RefMatch 三种跟踪模式](assets/images/refmatch/refmatch-tracking-modes.svg)

| 模式 | 匹配对象 | 最适合 | 特征 |
| --- | --- | --- | --- |
| 参考匹配（默认） | 每帧都与原始参考图匹配 | 主体 / 镜头运动明显的技能动画 | 抗累积漂移；最稳定；每帧都要付出匹配成本 |
| 递归匹配 | 首帧对参考图，之后每帧对上一帧的裁剪结果 | 缓慢偏离参考的长序列 | 接力式跟踪；避免把累积差异全压到一帧上 |
| 固定框裁剪 | 只在首帧匹配一次，之后复用同一变换 | 机位锁定、主体近乎静止 | 最快：后续帧只需解码 + 重采样 |

## 6. 系统架构与职责边界

RefMatch 分层为前端工作台、后端 API、核心引擎与运行时支撑。受约束的数据契约把上传、运行时预览、最终导出与任务状态保持在不同边界内。

![RefMatch 系统架构](assets/images/refmatch/refmatch-architecture.svg)

- **前端工作台（Next.js）** —— 资产准备、ROI 选择、参数配置与结果可视化；只通过 REST 与 SSE 进度与后端通信，不做任何图像计算。
- **后端 API（FastAPI）** —— 项目范围的资产与结果；图像对匹配 / 参考对齐、视频批任务、模型与健康状态。
- **核心引擎** —— 匹配器（RoMa / LoFTR / SIFT / ECC / 光流）、几何（变换估计与网格裁剪）、对齐（ECC 细化与 ZNCC 仲裁）、质量评分与轨迹平滑——唯一执行图像计算的一层。
- **运行时支撑** —— 异步任务（守护线程 + SSE + 磁盘持久化）、设备选择（CUDA / CPU 自动检测）与项目存储。
- **数据边界** —— 上传、预览、导出与逐帧结果都位于项目目录下；任务状态单独持久化，服务重启后可恢复或标记为已中断。

## 7. 运行时协作

批量序列跟踪任务带着输入与参数提交；后端启动异步工作线程，逐帧匹配或复用变换、稳定裁剪并写入磁盘，同时通过 SSE 推送进度。可选的轨迹平滑在所有帧完成后按锁定尺寸重渲染；随后帧结果即可供预览与导出。

## 8. 质量、安全与运行时边界

### 8.1 质量指标

| 指标 | 含义 |
| --- | --- |
| 质量评分 | 置信度、内点比例、重投影误差与空间覆盖率的加权融合——整体可靠性 |
| 内点比例 / 数量 | RANSAC 下几何一致的对应点占比与数量——匹配鲁棒性 |
| 重投影误差 | 内点在估计变换下的平均残差——越低越精确 |
| 内容相关性（ZNCC） | 参考 ROI 与裁剪结果之间的零均值归一化互相关；对光照与重复纹理稳健；用于仲裁候选变换并校正评分 |

工作台的质量环会给出可读建议：高分可直接导出；中等分建议检查叠加视图；低分则提示复核 ROI 与资产。

### 8.2 预览与源资产隔离

- 缩放、平移、显隐与视图切换只更新显示状态；不改变匹配输入，也不修改源资产。
- 结果预览与裁剪导出写入项目目录下的独立位置，绝不覆盖原件。

### 8.3 设备与运行状态

- 设备选择：自动 / CUDA / CPU。自动模式探测 CUDA 可用性，失败则回退 CPU。
- 状态上报设备、GPU 型号、显存占用与兼容性告警；显存不足会被显式提示。
- 深度匹配器权重在进程内首次使用时加载，后续任务复用；任务跑在守护线程上，支持轮询与 SSE 进度，可随时取消。

## 9. 能力范围与环境要求

### 9.1 当前能力

| 能力 | 行为 |
| --- | --- |
| 两图区域配准 | 在参考图上标注 ROI；在目标上自动定位并裁剪；含对比 / 叠加 / 差异视图 |
| 序列 / 视频逐帧跟踪 | 对视频或序列目录的每一帧匹配并稳定裁剪；输出尺寸统一、帧间稳定 |
| 三种跟踪模式 | 参考 / 递归 / 固定框——按运动特性在稳定性与速度间取舍 |
| 多种匹配器与变换 | 深度匹配器（RoMa / LoFTR）与经典方法（SIFT / ECC / 光流），配合多种几何模型 |
| 质量评分 | 每个结果给出置信度、内点比例、重投影误差与 ZNCC 内容相关性 |
| 批任务与导出 | 异步任务 + 进度；支持静帧、序列 ZIP 与视频导出 |
| 本地执行 | 资产与计算全部留在本地；CUDA / CPU 自动选择的 GPU 加速 |

### 9.2 环境与依赖

| 项目 | 要求 |
| --- | --- |
| 部署 | 本地：FastAPI 后端 + Next.js 工作台 |
| 算力 | CUDA GPU 加速深度匹配器；无 GPU 时回退 CPU |
| 模型权重 | 深度匹配器（RoMa / LoFTR / XFeat）权重位于本地模型目录 |
| 输入 | 常见图片格式与视频；序列支持 png / jpg / webp / bmp / tif / tga / exr / ppm 等 |

### 9.3 当前边界

- 只面向「内容相同、位置 / 尺度 / 轻微透视不同」的区域配准——不做语义识别或目标检测；
- 每个任务一张参考图与一个目标资产（一张目标图或一段序列 / 视频）；
- 内容完全不同、大形变、严重遮挡或近乎无纹理的平面可能失败或需要人工复核；
- 质量评分只是辅助；关键资产仍应通过叠加 / 差异视图验收；
- 固定框裁剪只适用于机位锁定、主体近乎静止的情况；运动或尺度变化明显时应改用参考匹配或递归匹配。
